**Statuses**
- **Before ship**: must land before the AppExchange package goes to Security Review (ship =
  managed 2GP package with Surveys).
- **Waiting on owner**: needs a ruling, not engineering.
- **Open**: a real gap, not blocking the package; do when it fits.
- **Very nice to have**: owner-chosen extras; done when there is room.
- **Parked**: consciously not now. Leaves only by being scheduled or explicitly killed.
- **Done**: kept so its number still means something.

**Rules:** a status line is a claim, so re-check the code before acting on one, and change it
in the same PR that changes the truth. A new item points to where its spec lives (write the spec
first, park it second).

## Two gates to shipping

| Gate | Meaning | Contents |
| --- | --- | --- |
| **Packaging-ready** | Can go to Security Review | Every **Before ship** item |
| **Customer-ready** | A release a paying admin would not resent | Packaging-ready plus the criteria below |

Customer-ready criteria (from the 2026-09 review; state as of 2026-11-14):
1. Every main authoring action works without a mouse: select, reorder and delete are done; moving
   an item to another section or page is drag-only by owner choice ([BUILDER_KEYBOARD_SPEC](./specs/BUILDER_KEYBOARD_SPEC.md)).
2. No failure message names the wrong operation or hides at narrow widths: done (2026-09-06).
3. Testing a rule doesn't need its inputs re-entered: done (2026-09-06).
4. Nothing advertises unbuilt features: **not met**, the form template shelf still says
   "coming next" (#15).
5. Studio small text meets 4.5:1: addressed by the Formwork design system (PRs 429–440); not
   re-measured in this merge.
