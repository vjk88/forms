Flag these fast (verify they still exist before recommending — line numbers drift):

1. **Property panel has no progressive disclosure.** `propertyPanel.html` is one long vertical scroll per context. Form Settings stacks ~12 controls + 3 conditional destination sub-blocks. Element props stack label/render-as/custom-values/slider/help/placeholder/visibility. Recommend grouping into collapsible sections or sub-tabs (Style / Behavior / Logic). Highest-impact cognitive-load fix.

2. **`completionEditor` is an orphan component.** No `c-completion-editor` reference anywhere in lwc/. Completion UX was reimplemented in `propertyPanel` (Form Settings, the After-Submit + destination blocks) AND as inline preview in `formDesigner.html`. The standalone component is dead code that was nonetheless edited in the recent diff. Completion config is effectively DUPLICATED between propertyPanel and completionEditor. Recommend deleting completionEditor or consolidating.

3. **Guest double-submit risk (Critical).** `formPlayer.handleSubmitClick()` calls `form.submit()`; the submit button is NOT disabled and shows no spinner until `handleSuccess` sets `isSubmitted=true`. Guests writing real records can double-click → duplicate records. Fix: set an `_submitting` flag, disable the submit button + show spinner, clear on success/error.

4. **Palette typo `class="palette-gro up"`** in `fieldPalette.html` (~L90) — splits into two bogus classes, breaks the Required Fields group wrapper styling. Should be `palette-group`.

5. **Raw hex instead of tokens** in a few spots (see [[tokens]]): toast `#032d60`, success rings `#eafbe7/#eafbe8`, player section header `#f7f9fb`.

6. **Top app bar is custom, not SLDS.** Primary Forms/Surveys nav + name/version dropdowns are hand-rolled buttons/menus. Works and looks clean, but accessibility of the custom dropdowns (`dd-menu`) needs checking: no `role=menu`/`aria-expanded`/arrow-key nav, closes via a full-screen backdrop div. Flag for keyboard + SR support.

7. **No skeleton/optimistic states in builder load.** Save uses a status strip (good), but version/layout load and the player first paint rely on `lightning-spinner` on blank. Player especially could use a skeleton to avoid spinner-on-blank + layout shift.

8. **Error text as a sibling `<p>` beside label-hidden lightning-* controls** (seen in finalRuleEditor S2, 2026-09-23): not tied to the control (no aria-invalid / describedby, no red border). Push `setCustomValidity`+`reportValidity`. Same review: identical per-row accessible labels ("Field" x N), onchange-per-keystroke validation shouting mid-typing, focus lost after row delete/add inside modals, `role=status` rendered inside `lwc:if` (not announced), no double-click guard on `Modal.open`.

9. **Button disabled by a problem the UI hasn't shown yet** (finalMappingSoql Check conditions, 2026-09-24): `checkDisabled` reads `problems` but they only render after Apply's `reportValidity()`. Any disabled state must show its reason next to it. Same review: SOQL-savvy admins quote answers (`'{Your email}'`) and quoted braces are silently literal text; dialogs with typed text (X/Esc, Clear all) discard it with no guard; programmatic `textarea.value` resets break native Ctrl+Z.

10. **"Not finished" with no stated reason** (finalMappingEditor card state, 2026-09-24): client `actionState` gates on rules (e.g. "search uses no answer") that no visible copy explains once conditions exist. Every incomplete/blocked gate needs a sentence on the step itself, not only in the dialog or at publish. Same review: "skippable" = not always-required OR hidden by a page/section/element rule (`FinalMappingRules.skippableElementIds`) — any hint saying only "make it required" is wrong for required-but-conditional questions.

12. **Custom in-Studio dialogs** (c/finalStudioDialog, 2026-09-25; owner ruled it over lightning/modal — don't re-litigate): check that the nested "Discard?" question makes the rest of the dialog `inert` (Shift+Tab escapes otherwise), the Studio behind is `inert` while open (pattern: `toggleAttribute('inert')` in finalFormStudio renderedCallback), `composedPath()` open-list sniffing can't see into child shadows (LWS/synthetic retarget), and css uses existing `--c-studio-dialog-shadow`/`--c-studio-radius-lg`/`--c-studio-warning-border` (there is NO `--c-studio-warning`). When a tab/mode is removed, grep publish-dialog area chips (`finalPublishDialog` still said "Data").

11. **"Go there" / jump links that land vaguely** (finalPublishDialog, 2026-09-24): repeated identical accessible names ("Go there" xN), no focus target after the modal closes, lands on the step top not the named section, and a sticky focus prop (`mappingFocus`) that re-fires on every later tab entry. Also: copy migrations miss Apex-side strings (FinalMappingSoql / FinalLookupService blockedReason) — grep classes for old nouns ("search", "tab", "filter") whenever UI vocabulary changes.

13. **Lazy-load in renderedCallback that resets its guard on error** (finalPropertyPanel listLookupObjects, 2026-09-25): catch sets `loaded=false` + reassigns `[]` -> rerender -> renderedCallback retries -> infinite Apex loop, and a "Loading..." placeholder that never ends. Also: widening a load key with a SERVER-returned id (viewer `effectiveVersionId` += `_servedVersionId` used inside `_load`'s dedupe key) makes the next wire/reconnect call reload and blank the form. And any new "unconfigured element" type (unbound lookup with no object) needs a publish refusal, not a runtime "not configured".

14. **Widening a shared allow-list silently changes old surfaces** (F2 Autofill B2, 2026-09-25): when one table (FinalAutofillRules) replaces a 5-type list, check EVERY caller of the old list (describeSourceFields fed the legacy in-rail editor that still only offers text destinations -> Date sources became publish traps), and check Apex `FinalSubmitService.answerTypeOf` fallthrough (unknown inputType -> 'Text', so 'reference'/'lookup' became "text" destinations). Also: a source-object change must drop `guestAllowed` ticks (same field names on a new object = silent guest disclosure), and a UI getter change (isSurvey now real) activates dormant branches — audit them.

15. **Viewer async sources that drop a stale reply WITHOUT clearing their pending entry** (F2 Autofill user source, 2026-09-25): an `_applySeq`/isRequestCurrent early-return that skips `_finish*Request` leaves Submit on "Finishing Autofill…" for the 10s timer, which then raises the form-wide "Could not fill these details" banner. Fingerprint moves come from Studio live edits (reconcile), `_applyAutofillPlan` on the LWR host (signed-in portal user), and `_prepareEditMode`/survey record switch (new session). A "once per key" dedupe that survives a NEW session means the new session never re-asks. Also: any new source must be added to `_dropCancelledAutofillRequests`, and timers must re-check isRequestCurrent before raising the banner. Non-link initial loads should pass `isInitialLinkLoad=true` or alwaysReplace nulls wipe static defaults.

16. **Correcting a draft in connectedCallback without re-running derived async work** (F2 Autofill slice D, 2026-09-26): an @api `rule` setter that kicks off typing/describe runs BEFORE later template attributes (form-type, spec) are set, so it reads the pre-correction object; the connectedCallback lock fixes `draft` but never re-calls `_typeRows()`, leaving rows untyped (fit + "field isn't on X" checks silently skipped). Whenever a setter normalizes and connectedCallback corrects, re-run the derived loads after the correction. Also: when a rail editor moves into a dialog, diff the old editor's non-obvious features (disclosure summary card, "Go to Fields" nav, preview test) and grep for now-dead event wiring (`onnavigatetab`).
- **Host-level key guards run LAST (bubble at host)** — inner template listeners (finalElementRenderer Enter→`advancekey`, nav handleKeydown, finalLookup) already fired; a viewer-host "block keys" guard cannot stop page-advance. Also flag blanket preventDefault+stopPropagation that eats Ctrl/Cmd shortcuts, F5, Escape for outer hosts (Autofill busy cover review 2026-09-27).
- **Contrast generators/checkers that share their surface model with their own tests** (brand B1, PR 401, 2026-10-24): the matrix only proves the generator meets its OWN surface list. Gaps found: section tints over the PAGE (One at a time open page + any authored section style; splitHero/oneAtATime bleed drop the panel) were missing (accent fell to ~4.3:1); input borders `--c-field-border` (30% text mix, ~1.85:1) never checked for WCAG 1.4.11; submit fill vs card (white/yellow brand = invisible button); Dark opaque fieldBg ~= boxed section (1.015:1). Always ask "which surfaces did the audit NOT list" and probe with an independent sweep.
- **Browser contrast scripts that check only the element's own clip** count `.slds-assistive-text` label contents as visible. Every label-hidden lightning-* control has an invisible `abbr.slds-required`; the ONLY visible platform asterisk is the single checkbox (`span.slds-checkbox`). LWR colour = `var(--dxp-g-destructive)`; SLDS rule = `var(--slds-g-color-error-base-40,#ea001e)` (both inherit through shadow, so a host-level hook works).
- **Live-normalizing text inputs** (brand B2 hex box, PR 402, 2026-10-24): an `oninput` handler that writes the NORMALIZED value back into the bound `value` rewrites the field mid-typing (`#1e3` is valid 3-digit hex -> field becomes `#11ee33`, the rest of `#1e3a8a` lands as junk). Probe: type the placeholder's own example one key at a time in jest. Validate on input, normalize only on blur/change. Same review: StudioDialog has no busy state, so a second Save click while saving runs the "missing field" branch and shows a false error; Cancel/Escape mid-save leaves the org record + uploaded file behind.
- **Pairwise "is a blend of" filters on bucketed colours** (finalBrandColors B2): any rule tested against EVERY other candidate is symmetric for near-duplicates — one colour split across a hue-bin/lightness-band edge by JPEG noise drops BOTH halves -> "no colours" for ~25% of hues. Always sweep hue 0-359 with +-4 noise in node (copy the module to .mjs) before trusting extraction tests built from flat pixel arrays.
- **Adding a second colour/role without re-wording single-colour copy** (brand B3, PR 403, 2026-10-24): "Your colour…" warnings, "Pick a colour first." and the empty-state go ambiguous once Main+Second exist; finalThemeCard's 4-dot strip shows ACCENT first, so a two-colour brand's gallery identity drops the Main colour. Also check validation symmetry: Second's hex error blocked Save but Main's (pre-existing) did not. Tap-to-assign swatches need the RESULT in the unpressed aria-label ("Use X as second colour"), not just "Use X".

## Focus Part B review (PR 405, 2026-10-25)
- Frozen-snapshot gate leaks come from UNGATED CSS, not tokens: a plain `:focus-visible { filter:none }` / `opacity:1` changes every old published form. Any focus CSS change must ride a token fallback or be called out as an owner-approved exception.
- Converting an `outline` (+ negative `outline-offset`) to a `box-shadow` ring silently moves it OUTSIDE the box: offset doesn't apply to shadows. Watch overhanging hit areas (`.file-item-x` -10px margins) and scroll containers (`.tab-list` overflow-x:auto, rail `overflow-y:auto`) that clip outer rings; ask for inset rings there.
- Section-local focus treatment on unthemed forms falls to the black/white fallback because the neutral token bag lacks `--c-field-bg`/`--c-text`; check helpers that read the bag for missing neutral keys.

## Picker preview geometry (feat/split-previews, 2026-10-27)
- An inherited width var (`--pv-card`) set on a class that is ALSO used for nested children (`.lt-card.flush` inside `.lt-split`) double-applies: rail/Split-Narrow cards leave an empty gutter. Check every nested use of a class that gained a var width.
- "Honest preview" claims: check the real renderer's container queries (Split stacks below 540px, so carded Narrow Split is stacked), pane side/ratio options, and density-dependent padding — a 1280px math model misses them.
- Small swatch-style cards (brand dialog Style row) reuse finalThemeCard; geometry props shrink them too unless the host opts out.
